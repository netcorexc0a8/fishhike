# 💻 FishHike: Конфигурация Технологического Стека

Данный файл содержит правила и особенности использования ключевых пакетов проекта.

## 1. Firebase (cloud_firestore, firebase_auth)

*   **Назначение:** Бэкенд, аутентификация, синхронизация данных.
*   **Правило 1 (Безопасность):** Все операции записи/редактирования/удаления в Firestore должны быть защищены правилами безопасности (`rules`) и разрешены только для аутентифицированного пользователя (`request.auth.uid != null`).
*   **Правило 2 (Модели):** При работе с Firestore *документами* в слое Data, необходимо использовать DTO (Data Transfer Objects), которые преобразуются в `Entities` (Domain-слой) перед передачей в UseCases.
*   **Правило 3 (UID):** Все коллекции, содержащие пользовательские данные (чек-листы, свои рецепты), должны быть вложены по пути: `users/{uid}/{collection_name}/{doc_id}`.

## 2. JSON Сериализация (json_annotation, build_runner)

*   **Назначение:** Автоматическая сериализация/десериализация моделей.
*   **Правило 1:** Все классы Model (в слое Data) должны использовать аннотацию `@JsonSerializable()`.
*   **Правило 2:** Для генерации кода использовать команду: `flutter pub run build_runner build --delete-conflicting-outputs`.

## 3. HTTP Client (dio)

*   **Назначение:** Выполнение HTTP-запросов (в основном к Open-Meteo API).
*   **Правило 1:** Использовать пакет `dio` (предпочтительнее стандартного `http` из-за интерцепторов и удобства).
*   **Правило 2:** Все запросы к API должны выполняться в `RemoteDataSource` в слое Data. Обработка ошибок (например, 404, таймаут) должна происходить в этом слое, с преобразованием в кастомные `Failure` (Domain-слой).

## 4. Локальный Кэш (path_provider & JSON)

*   **Назначение:** Офлайн-доступ к данным.
*   **Правило 1:** Использовать `path_provider` для получения директории для файлов данных (`getApplicationDocumentsDirectory()`).
*   **Правило 2:** Данные сохраняются в виде JSON-файлов (например, `recipes_cache.json`, `checklists_cache.json`).
*   **Правило 3:** Локальный `DataSource` (в слое Data) отвечает за чтение и запись этих JSON-файлов.

## 5. Управление Состоянием (flutter_bloc)

*   **Правило 1:** BLoC/Cubit должен зависеть только от UseCases.
*   **Правило 2:** В BLoC запрещено использовать Flutter-specific функции (напр., `print`, `setState` - очевидно, но важно).
*   **Правило 3 (UI):** Использовать `BlocBuilder`, `BlocListener` или `BlocConsumer` для реакции на изменения состояния и событий в UI.
