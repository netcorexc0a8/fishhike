# 📋 FishHike: Требования к Функционалу (MVP)

Это список требований к минимально жизнеспособному продукту (MVP). При выполнении задачи ИИ должен опираться на эти требования.

## A. Общие Требования

| ID | Требование | Примечание | Статус |
| :--- | :--- | :--- | :--- |
| G-01 | Кроссплатформенность | Поддержка iOS, Android, Web (с адаптивным UI). | |
| G-02 | Авторизация | Регистрация/Вход через Email/Password и Google Auth (Firebase Auth). | |
| G-03 | Офлайн-первый подход | Основной контент (чек-листы, рецепты) должен быть доступен и работоспособен офлайн. | |
| G-04 | Синхронизация | Все пользовательские данные (чек-листы, свои рецепты) синхронизируются с Firestore при наличии сети. | |
| G-05 | UI/UX | Дизайн должен быть стилизован под природу и интуитивно понятен. | |

## B. Модуль: Чек-листы (`features/checklist`)

| ID | Требование | Примечание | Статус |
| :--- | :--- | :--- | :--- |
| CH-01 | CRUD | Создание, просмотр списка, редактирование, удаление чек-листов. | |
| CH-02 | Сохранение прогресса | Отметка/снятие отметки с пункта. Прогресс должен сохраняться **локально** и синхронизироваться. | |
| CH-03 | Local Caching | Полное сохранение всех данных чек-листов в локальный JSON-файл (`path_provider`). | |
| CH-04 | Remote Sync | Синхронизация изменений с коллекцией `checklists` в Firestore. | |

## C. Модуль: Рецепты (`features/recipes`)

| ID | Требование | Примечание | Статус |
| :--- | :--- | :--- | :--- |
| RE-01 | Просмотр | Просмотр списка и деталей рецепта. | |
| RE-02 | CRUD (Пользовательский) | Создание, редактирование и удаление **своих** рецептов пользователем. | |
| RE-03 | Модерация (Клиентская) | Простая фильтрация стоп-слов при создании/редактировании рецепта (используется локальный список слов в `core/constants/stop_words.dart`). | |
| RE-04 | Жалобы | Возможность отправить жалобу на любой рецепт. Жалоба сохраняется в коллекцию `reports` в Firestore (содержит ID рецепта и ID пользователя). | |
| RE-05 | Local Caching | Кэширование всех данных рецептов в локальный JSON-файл для офлайн-доступа. | |

## D. Модуль: Прогноз Клёва (`features/forecast`)

| ID | Требование | Примечание | Статус |
| :--- | :--- | :--- | :--- |
| FO-01 | Интеграция с API | Использование **Open-Meteo API** для получения данных. | |
| FO-02 | Основные факторы | Отображение: Температура, Осадки, Давление, Скорость ветра, Фаза Луны. | |
| FO-03 | Лунный Прогноз | Расчет или вывод информации о благоприятном/неблагоприятном клёве (на основе фазы Луны и погоды). | |
| FO-04 | Кэширование | Кэширование последнего успешного прогноза в локальный JSON-файл для отображения офлайн. | |
